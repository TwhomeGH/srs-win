# 文件索引（單一入口）

**一句話**：程式碼是 API 的唯一真實來源，API 參考由 Doxygen 產生；手寫文件只記錄決策、限制與操作步驟，不重複抄寫函式簽名。

## 最短路徑

| 目的 | 指令／位置 |
|------|-----------|
| 建置（Windows，預設） | `cmake --build trunk/ide/srs_msvc/build --config Debug` |
| 全功能（RTC／SRT） | `cd trunk/ide/srs_msvc; cmake --preset windows-full; cmake --build --preset windows-full-debug` |
| 跑事件迴圈測試 | `ctest --test-dir trunk/ide/srs_msvc/build -C Debug -R st-event-loop-test` |
| 產生 API 參考 | `doxygen Doxyfile` → `_site/api/index.html` |
| 發佈文件站 | push `develop`（Pages workflow：changelogkit ＋ Doxygen） |
| 變更歷史 | `Docs/ChangeHistory.md`（由 changelogkit 解析） |
| 待辦 | `TODO.md`（唯一清單） |

## 文件原則

1. **不重複**：API 簽名、參數、回傳值只寫在原始碼註解，由 Doxygen 抽出；手寫文件只說明「為什麼」與「怎麼用」。
2. **單一入口**：新增文件時先更新本索引；`README` 與 Pages 只連到這裡與各主題，不再各自維護目錄。
3. **可驗證**：文件中的指令必須是實際可執行的最短指令；改動後以 CI（Pages／Nightly）或本機指令驗證。
4. **決策留痕**：版本取捨、移除元件、已知限制寫進 `組件盤點與技術債.md` 與 `ChangeHistory.md`，不要只留在對話。
5. **註解即文件**：公開 API 的註解使用 Doxygen 格式（`@param`／`@return`／`@brief`），讓產出的 API 頁面可讀。

## API 註解範例

```cpp
/**
 * @brief Close the listener and release its file descriptor.
 *
 * Safe to call more than once; the second call is a no-op.
 */
void close();
```

## 本機產生 API（免安裝 Doxygen）

```powershell
docker run --rm -v "${PWD}:/src" -w /src ubuntu:24.04 `
  bash -lc "apt-get update -qq && apt-get install -y -qq doxygen >/dev/null && doxygen Doxyfile"
```

輸出：`_site/api/index.html`。若只想檢查設定，執行 `doxygen -s -g Doxyfile.check` 後比對差異。
