# 功能旗標與能力自檢

> [!TIP]
> 這篇說明「這個 SRS build 到底編進了哪些能力」，以及 console 如何顯示。
> 建置流程見 [建置與執行說明](建置與執行說明.md)。
>
> 注意：**build capability（編進 binary）** 與 **config enabled（設定開啟）** 是兩件事。RTC 可能已編進，但 `rtc_server` 沒開；反過來不可能。

## 為什麼需要單一來源

SRS 有兩套 feature flag 產生方式：

```text
Linux   trunk/auto/auto_headers.sh
Windows trunk/ide/srs_msvc/CMakeLists.txt
```

兩邊的偵測工具不同，但原始碼必須看到一致的巨集。之前的做法容易出現：

```text
Windows 有 SRS_AUTO_RTC_USE
Linux 只有 SRS_RTC
```

現在由一個 header 統一別名與 bool：

```text
trunk/src/core/srs_feature_flags.hpp
```

它不負責「偵測」，只負責把各 lane 的輸入正規化成原始碼預期的形式。

## 輸入與輸出

| 來源 | 可能輸入 |
| --- | --- |
| Linux configure | `SRS_RTC`、`SRS_SRT`、`SRS_H265`、`SRS_SSL`、`SRS_GB28181`、`SRS_HDS` |
| Windows CMake | `SRS_AUTO_RTC`、`SRS_AUTO_SRT`、`SRS_AUTO_H265`、`SRS_AUTO_SSL`、`SRS_AUTO_GB28181` |
| 共用 header | 正規化為 `SRS_AUTO_*`、`SRS_AUTO_*_USE`、`SRS_*_BOOL` |

例如：

```text
SRS_RTC                       → SRS_AUTO_RTC + SRS_AUTO_RTC_USE + SRS_RTC_BOOL true
SRS_AUTO_SRT                  → SRS_AUTO_SRT_USE + SRS_SRT_BOOL true
SRS_H265                      → SRS_AUTO_H265 + SRS_AUTO_H265_USE
SRS_GB28181                   → SRS_AUTO_GB28181 + SRS_GB28181
```

缺少 alias 會在編譯期直接 `#error`，不會默默變成關閉。

## 目前各 lane 的能力

以下是實際 `/api/v1/config` 的 `capabilities`（2026.11 驗證）：

| Capability | Windows default | Windows full | Linux Docker |
| --- | --- | --- | --- |
| RTC | ❌ | ✅ | ✅ |
| SRT | ❌ | ✅ | ✅ |
| HLS | ✅ | ✅ | ✅ |
| DASH | ✅ | ✅ | ❌ |
| H.265 | ✅ | ✅ | ✅ |
| GB28181 | ✅ | ✅ | ❌ |
| SSL | ✅ | ✅ | ✅ |
| DVR | ✅ | ✅ | ✅ |

> 這張表是**編譯能力**，不是「服務已啟用」。HLS／DVR／DASH 是否真的產出，仍要看 vhost 設定。

## API

`GET /api/v1/config` 現在同時回傳：

```json
{
  "data": {
    "capabilities": {
      "rtc": true,
      "srt": true,
      "hls": true,
      "dash": false,
      "h265": true,
      "gb28181": false,
      "ssl": true,
      "dvr": true
    },
    "enabled": {
      "rtc": true,
      "srt": true,
      "hls": true,
      "dash": false,
      "dvr": false
    }
  }
}
```

| 欄位 | 含義 |
| --- | --- |
| `capabilities` | binary 是否編進該能力 |
| `enabled` | 目前設定是否開啟（vhost／server） |

console 的「設定 → 建置能力」表格同時顯示：

```text
能力 | 建置 | 設定 | 狀態
```

- `建置`：`capabilities`
- `設定`：`enabled`；沒有 runtime 開關的能力顯示 `-`
- `狀態`：`可用` 只在 build 與設定都存在時成立；純編譯能力顯示可用，但不代表已啟用

## 新增或修改 feature flag

1. 在 Linux `auto_headers.sh` 與 Windows CMake 產生同一個 canonical 輸入。
2. 若是新別名，優先加在 `srs_feature_flags.hpp`，不要在兩個 generator 各寫一次。
3. 若是新能力，補上：
   - `srs_feature_flags.hpp` 的正規化
   - `/api/v1/config` 的 `capabilities`
   - console 的 `capabilityRows`
   - 對應測試與文件
4. 執行：

```powershell
pwsh dev/check.ps1
pwsh dev/check.ps1 -Full
pwsh dev/local-deploy.ps1 -Deploy
npm --prefix ui test
```
