# 平台移植契約

> [!TIP]
> 這份文件定義「同一個 SRS 原始碼在不同平台必須有一致行為」的最小契約。
> 它不是 API 參考，也不是功能清單；實作細節見 [Windows 移植技術文件](Windows移植技術文件.md)。
>
> 目前正式維護的 lane 是 **Windows x64** 與 **Linux x64**。macOS 與 ARM64 尚未驗證，不能因為程式能編譯就視為支援。

## 1. 狀態用語

| 狀態 | 含義 |
| --- | --- |
| **Verified** | 有可重現測試或 CI 證據 |
| **Implemented, unverified** | 已有實作，但缺少對應回歸測試 |
| **Not supported** | 明確不支援；必須 fail-loud，不可假成功 |
| **Out of scope** | 目前不承諾，也不阻擋功能開發 |

## 2. Build Contract

### 2.1 支援的建置 lane

| Lane | 建置入口 | 狀態 |
| --- | --- | --- |
| Windows x64 default | `trunk/ide/srs_msvc`＋`windows-default` preset | Verified |
| Windows x64 full（RTC／SRT） | `windows-full` preset＋vcpkg | Verified |
| Linux x64 | `trunk/configure`＋Docker／Linux CI | Verified |
| macOS x64／ARM64 | 尚未建立 | Out of scope |
| Windows ARM64 | 尚未建立 | Out of scope |
| Linux ARM64 | 尚未建立 | Out of scope |

### 2.2 來源清單

同一份 app source 必須同時出現在：

```text
trunk/src/app/*.cpp
trunk/configure
trunk/ide/srs_msvc/CMakeLists.txt
```

檢查入口：

```powershell
pwsh dev/check-source-lists.ps1
```

新增檔案漏列時，本機與 Linux CI 必須失敗；不要只修其中一邊。

### 2.3 Feature flags

canonical header：

```text
trunk/src/core/srs_feature_flags.hpp
```

輸入可以是 Linux 的 `SRS_*` 或 Windows 的 `SRS_AUTO_*`；輸出必須一致：

```text
SRS_AUTO_<feature>
SRS_AUTO_<feature>_USE
SRS_<feature>_BOOL
```

規則：

- 新 feature 不得在兩個 generator 各寫一份 alias。
- 缺少 alias 時以 `#error` 阻擋，不可默默關閉。
- `/api/v1/config` 的 `capabilities` 必須反映編譯能力；`enabled` 只反映執行時設定。

## 3. OS Contract

### 3.1 檔案開啟與替換

| 行為 | 契約 | Windows | Linux | 證據 |
| --- | --- | --- | --- | --- |
| 唯讀開檔允許被替換 | 開檔時允許 delete sharing | `FILE_SHARE_READ｜WRITE｜DELETE` | POSIX 自然支援 | `file-share-test` |
| 目的檔已存在時替換 | 必須覆寫，不可回 `EEXIST` | `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`；必要時兩段式 | `rename()` | `path-rename-test` |
| 替換失敗 | 回 `-1` 並設定可判讀的 `errno` | Win32 → errno 映射 | 原生 errno | `path-rename-test` |
| 讀者仍在讀取 | 不應讓 HLS refresh 失敗 | 舊檔改名後再放入新檔 | POSIX rename 語意 | `file-share-test` |

不得用 CRT `rename()` 直接取代 `srs_path_rename()`；Windows 的語意不同。

### 3.2 Socket 與事件迴圈

| 行為 | 契約 | Windows | Linux | 證據 |
| --- | --- | --- | --- | --- |
| 多工 | 不 busy spin、timeout 可預期 | `select()`，`FD_SETSIZE=8192` | 原生 poll／epoll 路徑 | `st-event-loop-test` |
| 關閉連線 | fd 要回收，不可留下殭屍 | `closesocket`＋select 例外集 | POSIX close | 部分 unverified |
| 非阻塞 | 行為一致 | `ioctlsocket(FIONBIO)` | `fcntl(O_NONBLOCK)` | 啟動與 smoke |
| 事件層替換 | 未經量測不得改 IOCP | 目前 select | 目前 upstream 路徑 | Out of scope |

### 3.3 PID／單實例鎖

| 行為 | 契約 | Windows | Linux | 證據 |
| --- | --- | --- | --- | --- |
| 同時間只能一個實例 | 第二個啟動必須失敗 | `LockFileEx` | POSIX 檔案鎖 | 啟動測試 |
| stale pid | 不可永久阻止啟動 | 鎖釋放後可重建 | 同左 | 啟動測試 |
| 鎖失敗 | 回錯，不可假成功 | `ERROR_LOCK_VIOLATION` 等映射 | 原生 errno | `win-compat-test` |

### 3.4 行程與訊號

| 行為 | 契約 | Windows | Linux | 證據 |
| --- | --- | --- | --- | --- |
| spawn 子行程 | 支援時要有一致 exit status | **Not supported**（`ENOSYS`） | POSIX fork／exec | 未接入 |
| 優雅關閉 | Ctrl+C／服務停止可清理 | `SetConsoleCtrlHandler` | POSIX signal | 啟動／停止 |
| 重新載入 | 不可假成功 | 不支援 inotify | inotify | `win-compat-test` |
| daemon | Windows 不支援 double-fork | foreground 模式 | POSIX | 已知限制 |

`fork()`／`kill()` 在 Windows 必須回 `-1`＋`ENOSYS`；需要子行程的功能應在設定或啟動階段明確拒絕。

### 3.5 時間與錯誤碼

| 行為 | 契約 | Windows | Linux |
| --- | --- | --- | --- |
| monotonic clock | 不受系統時間調整 | QPC | `clock_gettime` |
| 檔案錯誤 | 呼叫端可從 `errno` 判斷 | `srs_win32_error_to_errno` | 原生 errno |
| socket 錯誤 | 與檔案錯誤分開 | `WSAGetLastError` | 原生 errno |
| 不支援 API | fail-loud | `-1`＋`errno` | N/A |

### 3.6 動態載入與 Unix socket

| 能力 | Windows | Linux | 契約 |
| --- | --- | --- | --- |
| `dlopen`／`dlsym` | stub 或明確不支援 | 原生 | 不可假裝載入成功 |
| AF_UNIX | 非原生；不可依賴 | 原生 | 需要本機 IPC 時先設計替代方案 |

## 4. ABI Contract

### 4.1 Context switch

| 平台 | 實作 | 狀態 | 驗證 |
| --- | --- | --- | --- |
| Windows x64 | `md_win64.asm`（MSVC x64） | Verified | `st_abi_probe.asm`＋`st-event-loop-test` Debug／Release |
| Linux x64 | upstream `st` asm | Verified（上游路徑） | `st-event-loop-test` |
| macOS／ARM64 | 尚未建立 | Out of scope | 無 |

Windows x64 必須保存：

```text
RBX、RBP、RDI、RSI、R12–R15
XMM6–XMM15（各 16 bytes）
MXCSR、x87 control word
```

規則：

- 只允許在 ABI 邊界使用組語；不要把業務邏輯寫進 `.asm`。
- 任何 context switch 變更都必須同時更新 ABI probe。
- Debug 通過不代表 Release 通過；兩者都要測。
- 新增平台時必須先有對應 probe，才可宣告支援。

## 5. Capability Matrix

`/api/v1/config` 的 `capabilities` 是編譯能力，`enabled` 是執行時設定。以下為目前驗證狀態：

| 能力 | Windows default | Windows full | Linux x64 | macOS | ARM64 | 證據 |
| --- | --- | --- | --- | --- | --- | --- |
| RTMP | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | smoke |
| HTTP-FLV | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | console／smoke |
| HLS | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | HLS 測試 |
| DASH | ✅ | ✅ | ❌ | 未驗證 | 未驗證 | capabilities |
| DVR | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | capabilities |
| RTC／WebRTC | ❌ | ✅ | ✅ | 未驗證 | 未驗證 | RTC E2E |
| SRT | ❌ | ✅ | ✅ | 未驗證 | 未驗證 | SRT 推流／smoke |
| H.265 | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | capabilities |
| GB28181 | ✅ | ✅ | ❌ | 未驗證 | 未驗證 | capabilities（端到端未驗證） |
| SSL | ✅ | ✅ | ✅ | 未驗證 | 未驗證 | build／API |
| FFmpeg 內部轉碼 | ❌ stub | ❌ stub | 系統 FFmpeg | 未驗證 | 未驗證 | 已知限制 |

「未驗證」不是支援；功能文件不得把它寫成 ✅。

## 6. 平台邊界

### 6.1 Windows

```text
trunk/ide/srs_msvc/
  CMakeLists.txt
  CMakePresets.json
  force_include.h
  compat/
  ffmpeg_stubs/
trunk/3rdparty/st-srs/
  md_win64.asm
  md.h
```

- Windows 建置、相容標頭與 stub 集中在 `srs_msvc`。
- `trunk/src` 的 `_WIN32` 分支只保留無法由 adapter 表達的邊界。
- 新增 stub 必須 fail-loud，並加 `@note`。

### 6.2 Linux／macOS

- Linux 使用 `trunk/configure` 與 POSIX 路徑。
- macOS 不會因為是 POSIX 就自動支援：`kqueue`、Mach-O ABI、簽章與檔案語意仍需獨立驗證。

### 6.3 不變規則

- 不改 `compat/` 的失敗語意，除非同時更新本契約與測試。
- 不把 Windows 專屬 `#ifdef` 散落到 app／protocol。
- 不用「能編譯」當成「已支援」。
- 不在沒有 capability test 的情況下承諾新平台。

## 7. 測試對應

| 契約 | 測試 | 入口 |
| --- | --- | --- |
| 檔案替換 | `path-rename-test` | `dev/check.ps1`／ctest |
| 開檔 sharing | `file-share-test` | 同上 |
| 事件迴圈／協程 | `st-event-loop-test` | 同上 |
| ABI | `st_abi_probe.asm` | 同上 |
| POSIX stub／errno | `win-compat-test` | 同上 |
| PID lock duplicate | `dev/test-platform-contract.ps1` | `dev/check.ps1 -Platform`／Nightly |
| PID lock stale restart | 同上 | 同上 |
| HTTP／RTMP／console | `dev/smoke-test.ps1` | Nightly／Release |
| RTC 媒體 | `dev/rtc-e2e.ps1` | Windows full CI |
| Linux 建置 | `.github/workflows/linux-build.yml` | Linux CI |

## 8. 變更流程

1. 先確認變更屬於 Build／OS／ABI 哪一種契約。
2. 更新本文件與對應測試；不要只改程式。
3. 若新增 feature flag，同步更新：
   - `srs_feature_flags.hpp`
   - `/api/v1/config` capabilities
   - console 能力表
4. 若新增平台，先列出 capability matrix 與未驗證項目。
5. 執行 `dev/check.ps1`、`dev/check.ps1 -Full`、Linux build；必要時跑 smoke／RTC E2E。

## 9. 目前明確缺口

| 缺口 | 狀態 | 何時處理 |
| --- | --- | --- |
| macOS 建置與 ABI | Out of scope | 有需求時 |
| Windows／Linux ARM64 | Out of scope | 有需求時 |
| `CreateProcess` 行程管理 | Not supported | 做 ingest／exec 時 |
| IOCP 取代 select | Out of scope | 有量測證據時 |
| FFmpeg 真實轉碼 | Not supported | 做轉碼功能時 |
| 連線關閉細節 | Implemented, unverified | 有 fd 洩漏證據時 |
| `srs_win32_compat.h` 重疊 | 技術債 | 結構清理批次 |
