# 已知限制與待辦事項

## 🔴 已知限制（by design）

這些限制是 Windows 平台本身的特性或刻意簡化的設計：

### 1. Daemon 模式不可用

- **原因**: Windows 不支援 `fork()` double-fork 慣用語
- **目前行為**: 以 foreground 模式執行，顯示警告
- **程式碼位置**: `trunk/src/main/srs_main_server.cpp` line 455-462
- **解決方案**: 使用 `Start-Process` 背景執行，或用 `nssm` 註冊為 Windows 服務

### 2. 無行程管理（fork）

- **影響功能**:
  - `exec` — 無法 spawn ffmpeg 轉碼子行程
  - `ingest` — 無法從外部來源拉流
  - 任何依賴 `fork()` + `exec()` 的功能
- **原因**: Windows 不支援 `fork()`，`spawn()` 尚未實作
- **可能的改善方向**: 使用 `CreateProcess()` + `_spawn()` 系列函式實作

### 3. 無 inotify（設定熱更新）

- **影響功能**: `SRS_RELOAD` 訊號、設定檔自動重載
- **目前行為**: `inotify_init1()` 回傳 `ENOSYS`
- **程式碼位置**: `trunk/ide/srs_msvc/compat/sys/inotify.h`
- **解決方案**: 重啟 SRS 以載入新設定

### 4. `select()` 而非 `epoll()`

- **影響**: 高併發連線數時效能較差
- **FD_SETSIZE**: 設定為 8192（單一行程同時連線上限）
- **程式碼位置**: `trunk/3rdparty/st-srs/md.h` line 193 (`#define MD_HAVE_SELECT`)
- **改善可能性**: 可使用 `IOCP` (I/O Completion Ports) 實作高效事件系統，但需要大幅修改 st-srs

### 5. 訊號處理 Stub

- **影響功能**:
  - `SIGUSR1` / `SIGUSR2` — 重新載入設定
  - `SIGHUP` — 優雅關閉
  - `SIGPIPE` — 中斷的 pipe/socket 寫入
- **目前行為**: `sigaction()` 為 no-op
- **解決方案**: 使用 `SetConsoleCtrlHandler()` 處理 CTRL+C 等事件

### 6. FFmpeg 內部 API Stub

- **影響**: SRS 內部無法直接轉碼（codec API stub 回傳 `-1`）
- **目前行為**: 可連結，但 `avcodec_open2()` 等 API 回傳錯誤
- **解決方案**: 
  - 快速方案：Spawn 外部 `ffmpeg.exe`（但 fork 暫不可用）
  - 完整方案：實作 `CreateProcess()` 啟動 ffmpeg.exe

### 7. 無 UNIX Domain Socket

- **影響**: AF_UNIX socket 被映射為 AF_INET（不適用於本機 IPC）
- **程式碼位置**: `trunk/ide/srs_msvc/compat/sys/socket.h`

### 8. 僅支援 x64

- 無 x86 (32-bit) 支援
- 無 ARM64 Windows 支援（如 Surface Pro X）

### 9. MSVC Debug Iterator 相容性

- `_ITERATOR_DEBUG_LEVEL=0` 設於 Debug 組態
- 若 vcpkg 套件以 `/MDd` 編譯，可能發生 iterator 不相容
- **解決方案**: Release 組態不會有此問題

## 🟡 已知疑點（需驗證）

### 1. Cygwin64 IPv6 解析 Bug

- **檔案**: `trunk/src/utest/srs_utest_kernel.cpp` line 7274
- **問題**: IPv6 位址 `2001:0db8:85a3:0:0:8A2E:0370:7334:`（結尾冒號）在 Cygwin64 上被判定為合法
- **狀態**: 僅在 Cygwin 環境有問題，MSVC 可能不受影響（但需測試）

### 2. HTTP Stack Windows 路徑處理

- **檔案**: `trunk/src/protocol/srs_protocol_http_stack.cpp` line 1619
- **註解**: "But Windows puts spaces here! Yay."
- **問題**: Windows URL zone identifier 包含空白字元

## 🟢 建議改善事項

### 短期（低風險）

1. **減少 `force_include.h` 與 `srs_win32_compat.h` 重複**
   - 兩個檔案都有 `ssize_t`、POSIX 函式映射等定義
   - 建議：將 `srs_win32_compat.h` 併入 `force_include.h` 或反之

2. **統一台頭管理**
   - 部分 Windows 標頭在 3 個以上檔案中重複 include
   - 建議：集中至 `srs_core_platform.hpp` 管理

3. **改善 `rebuild.ps1`**
   - 目前路徑為絕對路徑 (`F:\srs\...`)
   - 建議改為相對路徑，以利在不同機器上使用

4. **移除 `trunk/build/msvc/` 殘留目錄**
   - 此目錄有過時的 .obj 但無 srs.exe
   - 可能是舊版 CMake 嘗試的殘留

### 中期（中等風險）

5. **使用 `CreateProcess()` 實作行程管理**
   - 替代 `fork()` + `exec()`，讓 ffmpeg/ingest 功能可用

6. **使用 `IOCP` 實作高效事件系統**
   - 替代 `select()`，大幅提升高併發效能
   - 需修改 st-srs 的事件層

7. **實作 Windows 服務模式**
   - 使用 `RegisterServiceCtrlHandler` / `SetServiceStatus`
   - 替代 daemon 模式

8. **實作 `SetConsoleCtrlHandler` 訊號處理**
   - 替代 POSIX signal 處理
   - 讓 CTRL+C、視窗關閉等事件能優雅關閉 SRS

### 長期（高風險）

9. **ARM64 Windows 支援**
   - 需新增 `md_win64_arm64.asm`（或使用不同機制）
   - 驗證 vcpkg 套件在 ARM64 上的可用性

10. **內部轉碼支援**
    - 解法一：在 Windows 上編譯真實 FFmpeg 並連結
    - 解法二：透過 FFmpeg C API 動態載入 DLL
    - 解法三：保持 stub，僅支援外部 ffmpeg.exe

11. **CI/CD 建置流水線**
    - 建立 GitHub Actions 自動建置 Windows 版
    - 自動測試基本功能（RTMP 推拉流）
