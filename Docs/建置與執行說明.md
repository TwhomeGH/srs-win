# SRS Windows 版 — 建置與執行說明

## 環境需求

| 項目 | 需求 |
| ------ | ------ |
| **作業系統** | Windows 10/11 x64 |
| **編譯器** | Visual Studio 2022 (Community/Professional/Enterprise) 含 MSVC v143 |
| **CMake** | 3.15+ |
| **vcpkg** | 用於 RTC／SRT；安裝位置不限，`dev/setup-vscode.ps1` 會自動尋找 |
| **MASM** | `ml64.exe` (隨 VS 2022 安裝) |

## 一鍵建置執行

```powershell
# 建置（不執行）
.\rebuild.ps1

# 建置並執行
.\rebuild.ps1 -Run

# 只執行（不重新建置）
.\rebuild.ps1 -Run -NoBuild

# 停止 SRS
.\stop.ps1
```

## 手動建置步驟

### 1. 安裝相依套件（vcpkg）

```powershell
# Install vcpkg if not already:
# git clone https://github.com/Microsoft/vcpkg.git <你的路徑>\vcpkg
# & <你的路徑>\vcpkg\bootstrap-vcpkg.bat

# Install required packages:
vcpkg install openssl srtp opus srt --triplet x64-windows
```

### 2. CMake Configure

```powershell
cmake -B trunk/ide/srs_msvc/build `
      -S trunk/ide/srs_msvc `
      -G "Visual Studio 17 2022" -A x64 `
      -DCMAKE_TOOLCHAIN_FILE="<你的路徑>/vcpkg/scripts/buildsystems/vcpkg.cmake"
```

> 若未使用 vcpkg，部分功能會自動降級（SSL、RTC、SRT 等將被停用）。

### 3. MSBuild

```powershell
msbuild trunk/ide/srs_msvc/build/srs.sln /p:Configuration=Debug /m
```

或使用 CMake:

```powershell
cmake --build trunk/ide/srs_msvc/build --config Debug
```

建置完成後，輸出目錄 `trunk/ide/srs_msvc/build/Debug` 會直接包含可執行的組合：`srs.exe`、`srs.pdb`、`test.conf`、`objs/` 與 OpenSSL 的 `libcrypto-*.dll`／`libssl-*.dll`。整個目錄可以複製到其他機器執行（Release 版不含 debug CRT 相依）。

### 4. 執行

```powershell
.\trunk\ide\srs_msvc\build\Debug\srs.exe -c .\trunk\ide\srs_msvc\build\Debug\live.conf
```

## 全功能建置（RTC／SRT）

預設的 `windows-default` 只啟用系統 OpenSSL，RTC／SRT 會顯示 `RTC=FALSE, SRT=FALSE`。要啟用兩者，使用 vcpkg 安裝 MSVC 可用的依賴，再套用 `windows-full` preset：

```powershell
# 第一次或 vcpkg 搬家後：建立 workspace junction（自動尋找 vcpkg）
pwsh dev/setup-vscode.ps1
# 找不到時明確指定：pwsh dev/setup-vscode.ps1 -VcpkgRoot D:\tools\vcpkg

# 用 junction 安裝依賴（不需要記住 vcpkg 的磁碟機）
& .vscode\vcpkg\vcpkg.exe install libsrtp libsrt opus --triplet x64-windows

cd trunk/ide/srs_msvc
cmake --preset windows-full
cmake --build --preset windows-full-debug
ctest --preset windows-full-test
```

| preset | 用途 | 輸出目錄 |
| -------- | ------ | ---------- |
| `windows-default` | 日常開發（RTC／SRT 關閉） | `trunk/ide/srs_msvc/build` |
| `windows-full` | 全功能（vcpkg 依賴） | `trunk/ide/srs_msvc/build-full` |

> `windows-full` 透過 `.vscode/vcpkg` junction 找 toolchain，不再要求 `VCPKG_ROOT` 或固定磁碟機；第一次請先跑 `dev/setup-vscode.ps1`。若 junction 不存在，configure 會直接失敗，不會默默退回關閉功能。
> FFmpeg 仍是 stub；若要 RTC 音訊／內部轉碼，需另外接真實 FFmpeg 7.x（見 `Docs/組件盤點與技術債.md`）。

## 設定檔說明

預設設定檔：`trunk/conf/test.conf`（建置時會複製到輸出目錄，名為 `test.conf`）。

`test.conf` 目前使用下列埠：

```conf
rtmp {
    listen          19350;
}
http_api {
    enabled         on;
    listen          1985;
}
http_server {
    enabled         on;
    listen          8088;
}
```

常用調整：

| 設定 | 說明 |
| ------ | ------ |
| `rtmp.listen` | RTMP 監聽埠 |
| `http_api.listen` | HTTP API 埠（smoke test 使用 1985） |
| `http_server.listen` | HTTP 靜態檔／HLS 埠 |
| `hls_path` | HLS 輸出目錄，預設 `./objs/nginx/html`（相對於工作目錄） |
| `srs_log_tank`／`srs_log_file` | `console` 或 `file`，檔案預設 `./objs/srs.log` |
| `srs_log_level` | `trace`／`debug`／`info`／`warn`／`error` |

> **注意**: 設定檔中的路徑請使用正斜線 `/` 或跳脫反斜線 `\\`；執行前確認工作目錄下有可寫的 `objs/`。
>
> HLS 預設位置是 `./objs/nginx/html`，**相對於 SRS 的工作目錄**，不是 Windows `%TEMP%`。若從 `%TEMP%` 或其他目錄啟動，HLS 會跟著跑到那裡；請用 `dev/srs-dev.ps1`（cwd 固定在 `dev/runtime/windows`），或在設定檔用 `work_dir`／絕對路徑指定。

## 驗證服務是否正常

```powershell
# 查看 SRS 是否在執行
Get-Process -Name srs

# 測試 HTTP API
curl http://localhost:1985/api/v1/versions

# 測試 RTMP 推流 (需另裝 ffmpeg)
ffmpeg -re -i video.mp4 -c copy -f flv rtmp://localhost/live/stream

# 測試 RTMP 播放
ffplay rtmp://localhost/live/stream
```

## 開發建議

### VSCode 除錯

完整的中斷點、`launch.json`／`tasks.json` 與生產版 `.exe` 偵錯流程請看 **[VSCode 除錯手冊](VSCode除錯手冊.md)**。重點：

- Windows 使用 `cppvsdbg`（Visual Studio 偵錯器），不是 `cppdbg`。
- `preLaunchTask` 指向 `cmake --build ... --config Debug`。
- `cwd` 設在輸出目錄，讓 `test.conf` 與 `objs/` 相對路徑正確。

### Visual Studio 整合

```powershell
# 直接產生 VS 方案並開啟
cmake --open trunk/ide/srs_msvc/build
```

### Debug 技巧

1. **日誌層級**: 設 `log_level debug` 或 `log_level verbose` 以取得更多資訊
2. **PDB 符號**: `srs.pdb` 已隨 build 產生，可用 VS 或 WinDbg 附加偵錯
3. **stderr 輸出**: 錯誤訊息預設輸出至 stderr，可導向檔案：

   ```powershell
   .\srs.exe -c live.conf 2> srs_err.log
   ```

### CMake 升級後：CMAKE_ROOT 快取失效

CMake 版本更新後，舊的 `CMakeCache.txt` 仍可能記著舊的 `CMAKE_ROOT`。例如 CMake 已升到 4.4，cache 卻還指向：

```text
C:/Program Files/CMake/share/cmake-4.3
```

會出現：

```text
file failed to open for reading ... cmake-4.3/Modules/CMakePlatformId.h.in
Unknown CMake command "CMAKE_DETERMINE_COMPILER_ID".
```

這不是原始碼改動，而是 CMake binary 與 cache 不一致。處理方式：

```powershell
cd trunk/ide/srs_msvc

# 預設建置
cmake --preset windows-default --fresh

# 全功能建置
cmake --preset windows-full --fresh
```

`--fresh` 只重建 CMake cache／`CMakeFiles`，不會刪除已編譯的輸出。也可以刪除 `CMakeCache.txt` 與 `CMakeFiles/` 後重新 configure；不要手動修改 cache 內的 `CMAKE_ROOT`。

`dev/check.ps1` 會先檢查 cache 的 `CMAKE_ROOT`；路徑已不存在時自動執行 `--fresh`，再繼續建置。

## 清除重建

```powershell
Remove-Item -Recurse -Force trunk/ide/srs_msvc/build
# 然後重新執行 rebuild.ps1
```
