# 測試策略

**原則**：測試跟著它保護的程式碼走；能跑在本機、CI 與 PR 前的同一條命令，不在文件裡另外抄一份。

## 測試分層

| 位置 | 內容 | 指令 | 目前狀態 |
|------|------|------|----------|
| `dev/tests/` | C++ 原生回歸測試（st event loop、socket 行為） | `pwsh dev/check.ps1` | ✅ `st_event_loop_test.cpp` 已接 ctest |
| `ui/tests/` | Web 控制台單元測試（FLV 分析、API 錯誤分類） | `npm --prefix ui test` | ✅ Vitest |
| `trunk/src/utest/` | 上游 SRS 單元測試 | 尚未接建置 | ⚠️ 技術債，見 `組件盤點與技術債.md` |
| Nightly | 建置、ctest、UI 測試、RTMP handshake、`/console/` smoke | GitHub Actions | ✅ |

## 常用命令

```powershell
# 原生 C++（只重建 srs + st-event-loop-test，再跑 ctest）
pwsh dev/check.ps1

# 原生 + Web 控制台單元測試
pwsh dev/check.ps1 -Ui

# 只跑 Web 控制台測試
npm --prefix ui test

# 全功能（RTC/SRT）建置與測試
pwsh dev/check.ps1 -Full
```

## 命名與界線

- **C++**：`dev/tests/<area>_test.cpp`，以 `add_executable` + `add_test` 註冊；測試 binary 不進 PATH，不依賴外部服務。
- **Web**：`ui/tests/<module>.test.js`，只測純邏輯與 API 分類；需要 DOM／瀏覽器行為的流程交給 Playwright smoke，不放進 Vitest。
- **Fixture**：小型、可讀、由測試自己建立（例如 FLV bytes）；不要提交大型二進位或錄製檔。
- **外部依賴**：單元測試不打真實網路、不啟動 SRS；整合測試由 Nightly 的 smoke 負責。
- **每個 bug fix**：先補一個會失敗的測試，再修；例：AAC sample rate 解析、`ERR_NETWORK` 分類、離線保留資料。

## CI 的責任

`.github/workflows/windows-nightly.yml` 依序跑：

1. Configure／Build
2. `st-event-loop-test`（ctest）
3. `npm ci` → `npm test`（Vitest）
4. `npm run build` → 複製到 `objs/nginx/html/console`
5. Smoke：HTTP API、RTMP handshake、`/console/` 200

`test.yml` 與 `codeql-analysis.yml` 目前是停用狀態；不要把它們當成目前的測試保證。
